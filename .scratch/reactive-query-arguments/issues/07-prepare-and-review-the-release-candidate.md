# 07 — Prepare and review the release candidate

**What to build:** Reconcile the complete argument-bearing reactive query contract across release-facing documentation, generated surfaces, versioned package contents, and the supported verification gates, then produce an immutable independently accepted package candidate without publishing it.

**Blocked by:** 03 — Make React and Preact query arguments lifecycle-reactive; 04 — Propagate query arguments through Vue and Solid; 05 — Propagate query arguments through Svelte stores; 06 — Propagate query arguments through Lit and Inferno.

**Status:** ready-for-agent

- [ ] Reference, getting-started, architecture, framework, generated interface, and release-change documentation consistently describe trailing query arguments, JSON constraints, canonical equality, the 64 KiB limit, lifecycle behavior, and Custom-query-only support.
- [ ] Documentation preserves the distinction between explicit Team targeting and Team authorization and introduces no hidden current-Team state.
- [ ] The release version and change history follow the repository's current release convention after live verification of the checkout, tags, and registry state.
- [ ] Generated client runtime, generated server Bundle surfaces, public declarations, generated interface documentation, binaries, and source are regenerated by their owning build steps and pass parity checks.
- [ ] The complete supported Node 22 type, client-runtime, server-runtime, Bundle, adapter, documentation, build, package, and prepublish gates pass.
- [ ] Existing argument-free suites remain green and every configured database-adapter skip is reported explicitly rather than hidden behind a broad success summary.
- [ ] The packed tarball is inspected and contains the reviewed argument-bearing client declarations, generated client runtime, server runtime, documentation, and intended exact version.
- [ ] The tarball identity and contents correspond to one immutable candidate commit with no uncommitted release-byte changes.
- [ ] A separate read-only reviewer assesses the immutable candidate against both repository standards and the parent specification.
- [ ] Every actionable review finding is resolved, the candidate is repinned after any change, and the changed bytes receive fresh review and package inspection.
- [ ] The final handoff reports the candidate commit, tarball identity, commands and outcomes, generated parity, configured skips, review result, and remaining risks.
- [ ] No npm publication, downstream repository modification, or Client Input Chaser acceptance is performed under this ticket.
