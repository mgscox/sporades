# List And Inspect Jobs Across Runtime Sessions

Category: enhancement
Status: done

## What to build

Complete the server-runtime Job inspection surface for Capsule code. Harden
actor-scoped listing with pagination and filters while preserving the existing
current-user and Privileged server role visibility boundaries.

## Acceptance criteria

- [x] Normal server context can cursor-list only Jobs whose execution actor is the current captured user, and Privileged server role context can cursor-list all Jobs in the Capsule.
- [x] Server list supports bounded pagination plus status, handler, and creation-time filters with deterministic ordering.
- [x] List summaries omit payloads, results, and detailed failure metadata by default; explicit get remains subject to the same user or privileged visibility boundary.
- [x] `enqueuedBy` provenance never grants list or get visibility, and unauthorized IDs remain indistinguishable from unknown IDs.
- [x] Privileged server list/get operations execute through `ctx.privileged.run(...)` with mandatory bounded audit metadata.
- [x] Server inspection exposes no raw runtime tables, payload secrets, Server env values, tokens, cookies, browser credentials, or raw stack traces.
- [x] Tests cover user isolation, privileged enumeration, pagination and filters, redaction, audit evidence, and generated-runtime parity for the server API.
