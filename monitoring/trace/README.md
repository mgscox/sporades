# Standalone trace stack

This directory runs the first Sporades monitoring increment: authenticated OTLP/HTTP traces, a protected Jaeger UI, and a minimal readiness endpoint. It is independent of a Sporades Host and can run on a separate VM. Metrics, dashboards, alerts, Host binding, and Capsule instrumentation are delivered separately.

## Requirements and images

Use Linux `amd64` or `arm64`, Docker Engine 29.x and Docker Compose 2.40.3 or later (Compose 5.5.1 is also tested), Node.js 22.13+ for the local setup and smoke scripts, and disk space for the chosen trace retention. Image tags are fixed here: OpenTelemetry Collector contrib `0.138.0`, Jaeger `2.21.0`, BusyBox `1.37.0`, and gateway base Node `24.13.0-alpine3.23`. The named `traces` volume holds Jaeger Badger data. Jaeger retains spans for seven days by default (`TRACE_RETENTION=168h`). Collector and Jaeger have no published ports; only the gateway publishes a port. The gateway and Collector use bounded memory and request sizes, the Collector and Jaeger have bounded queues, and all services have memory, CPU, process, and log limits. Check the Docker volume's disk use against available space during operation; TTL is a retention limit, not a filesystem quota.

## Configure and start

From this directory, run `node setup.mjs` as the user who owns the stack directory. It creates `.env` with mode `0600` if absent and generates only missing `TRACE_INGEST_TOKEN` and `TRACE_UI_PASSWORD`. An existing value or operator-added key is left exactly as found. The example file contains placeholders only; do not copy its placeholder credentials into `.env`. Setup reports missing external setting names, never their values. It also writes `.private/credentials.json` with mode `0600`, selecting only the three gateway credentials from `.env`; Compose mounts that protected file into the gateway instead of interpolating credential values. The `.private/` directory is mode `0700`. A second generated file, `.compose.env`, contains only the settings Compose needs and the gateway UID/GID. On Linux, an unprivileged installer runs the gateway under that same UID. A root installer keeps `.private/` root-owned and transfers only the derived credential file to UID 1000, so the gateway stays non-root while other host users cannot traverse the private directory. Use `.compose.env` with `--env-file` so Compose does not parse dollar signs in the operator's credential values. Unquoted values are taken literally after `=`; one-line single-quoted values can escape an apostrophe with `\'`, and double-quoted values use JSON string escapes. This preserves literal `$`, `#`, colons, and spaces. Run setup again whenever `.env` changes. Keep `.env`, `.private/`, `.compose.env`, `certs/`, and private backups off Git and restrict filesystem access to the operator.

Choose one TLS arrangement in `.env`:

- **Direct TLS:** Keep `TRACE_TLS_MODE=tls`. Place your certificate chain and key in `certs/`, then set `TRACE_CERT_FILE=/certs/fullchain.pem` and `TRACE_KEY_FILE=/certs/privkey.pem`. Ensure the gateway UID recorded in `.compose.env` can read both files and traverse `certs/`; setup does not alter operator-supplied TLS file ownership. For a separately hosted monitoring VM set `TRACE_BIND=0.0.0.0`, open only the selected `TRACE_PORT` (default `8443`), and use `https://monitor.example:8443/v1/traces` as the OTLP/HTTP traces URL. Private CA clients must trust the supplied CA. The smoke script can use `NODE_EXTRA_CA_CERTS=/path/to/ca.pem`; do not disable TLS verification.
- **Existing TLS proxy:** Set `TRACE_TLS_MODE=proxy` and keep `TRACE_BIND=127.0.0.1`. Point an existing TLS reverse proxy on the same VM at `http://127.0.0.1:8443`, forwarding `/v1/traces`, `/health`, and the UI paths. The public ingestion URL is then `https://monitor.example/v1/traces`. Proxy mode refuses a non-loopback gateway bind. The proxy must terminate verified HTTPS for remote senders; never expose the loopback HTTP listener directly.

Run `node setup.mjs` again after editing, then `docker compose --env-file .compose.env up -d --build`. Ordinary `docker compose --env-file .compose.env down` preserves traces; adding `-v` destroys them. Use `docker compose --env-file .compose.env ps` and `GET /health` to check readiness. The endpoint returns only `{"ok":true}` with HTTP 200 after a bounded synthetic write through Collector and a Jaeger read, or only `{"ok":false}` with HTTP 503 otherwise. No watchdog is installed or required. The health probe itself writes a small synthetic trace, so each call uses a little retention space.

Send OTLP/HTTP trace requests to `/v1/traces` with `Authorization: Bearer <TRACE_INGEST_TOKEN>`. This credential cannot query traces. The Jaeger UI and query API use HTTP Basic with `TRACE_UI_USER` and `TRACE_UI_PASSWORD`. Keep each credential separate. The gateway rejects unauthenticated ingestion and UI access; raw backend ports stay inside the Compose network.

## Smoke test and restart proof

After startup, run `node smoke.mjs send`. It checks minimal readiness, rejected invalid ingestion and missing UI credentials, sends a real authenticated OTLP fixture, and queries it through the protected UI API. Save the trace ID printed by that command. Then run `docker compose --env-file .compose.env restart collector jaeger gateway` followed by `node smoke.mjs query TRACE_ID`; the same trace must remain queryable. With a private CA, set `NODE_EXTRA_CA_CERTS` for the smoke script. The scripts read `.env` locally and print no credentials. Never paste `.env` or `.private/credentials.json` into tickets or diagnostics.

## Backup, restore, and upgrades

Stop the stack before a consistent Badger backup. Back up the `sporades-traces_traces` Docker volume along with a private copy of `.env`, `.private/`, `certs/`, this directory's configuration, and any proxy config. Protect backups like credentials. To restore, stop the stack, restore the named volume and those files, run `node setup.mjs`, then run `docker compose --env-file .compose.env up -d --build`; the one-shot storage initializer restores Jaeger's non-root volume ownership. Verify with the smoke test. For upgrades, save a backup and the current pinned files, review new image versions and configuration, then run `docker compose --env-file .compose.env pull` and `docker compose --env-file .compose.env up -d --build`. Roll back using the saved files and volume backup if a new version changes storage format. Setup never rotates a credential during either path.
