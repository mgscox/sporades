# App messages use SDK APIs over the client transport

v2 allows app-defined messages over the existing Sporades client transport, exposed through `sporades/client` send and subscribe/filter APIs rather than raw WebSocket objects. App and server code provide unprefixed message type names; Sporades owns adding and reserving the internal `app.` prefix. Server code sends through context, such as `ctx.messages.send({ type, data, scope })`. Client-origin app messages are always mediated by declared capsule handlers, for example `capsule({ messages: { typing: message((ctx, data) => ...) } })`; the platform does not directly relay arbitrary client messages to other clients. App messages default to the current user's connected clients; app-wide broadcast with `{ scope: "all" }` is a server-code-only capability, and targeted client-origin delivery must be authorized server-side. This gives apps a real-time escape hatch while keeping core transport ownership inside Sporades and reserving platform message types.

Message handlers may return a response to the originating SDK call, while fan-out is explicit through server APIs such as `ctx.messages.send()`. v2 app messages are ephemeral, JSON-serializable only, and are not a replacement for durable table-backed events or binary file transfer.
